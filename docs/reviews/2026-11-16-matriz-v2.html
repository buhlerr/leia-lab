O bug que a v2 revelou

A transição v1 para v2 não funcionaria com o código anterior. O schema tem uma unique em (theme_id, risk_id). O apply desativava as linhas antigas e tentava inserir as mesmas chaves de novo.

antes

UPDATE risk_matrix SET active = false;
INSERT INTO risk_matrix (...)  -- viola a unique

As linhas antigas continuam no banco, inativas. O INSERT colide com elas.

depois

ON CONFLICT (theme_id, risk_id) DO UPDATE
SET description = EXCLUDED.description,
    criticality = EXCLUDED.criticality,
    party = EXCLUDED.party,
    norms = EXCLUDED.norms,
    active = TRUE

Risco alterado reaproveita a linha. Risco removido fica inativo. Nada é apagado.
